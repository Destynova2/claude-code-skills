# Editorial Lenses

Use this reference when the user asks for narrative strength, comprehension, memorability, attention, or mentions writers/public communicators.

## Boundary

Do not imitate a living author's style. Convert named influences into abstract craft principles.

Names such as Christian Jacq or Fabien Olicard are optional personal mnemonics, not authorities for the output. In default wording, prefer the principle names below and let credibility come from verified facts, platform rules, and the method bank.

For "Christian Jacq", privately map the request to the **trajectory lens**:
- protagonist with a clear role,
- constrained environment or operating pressure,
- quest expressed as a concrete mission,
- proof through trials and delivered outcomes,
- sober authority, not ornament.

For "Fabien Olicard", privately map the request to the **scan-and-recall lens**:
- reduce cognitive load,
- place the hook before the explanation,
- create a few stable anchors,
- use contrast and concrete examples,
- make the next action obvious.

## Trajectory Lens

Use when the profile feels technically correct but forgettable.

Pattern:

```text
Context: regulated / constrained environment.
Tension: risk, leakage, auditability, downtime, dependency, delivery friction.
Action: architecture, automation, hardening, product, team building.
Proof: metric, audit result, team size, artifact, public repo, talk.
Direction: what the candidate now helps buyers do.
```

Do:
- turn chronology into trajectory;
- show why the work matters;
- use only disclosable settings: regulated infrastructure, fintech PCI-DSS, scale-up, or air-gapped environment when the label itself is not confidential;
- keep authority quiet and factual.

Do not:
- dramatize beyond the facts;
- make the candidate sound mystical, heroic, or theatrical;
- bury proof after long philosophy.

## Scan-and-Recall Lens

Use when the profile is dense, jargon-heavy, or hard to remember.

### Anchor Heuristic

Pick a small number of anchors and repeat them consistently across headline, About, CV, and skills. Three is a useful heuristic, not a rule or evidence-backed constant.

Example:
- DevSecOps / Platform Engineering
- Sovereign AI / LLM Gateway / DLP
- Regulated / air-gapped environments

### 10-Second Test

After the first screen, the reader should know:
- what the person does,
- for whom,
- why they are credible,
- what to do next.

### Compression Rules

- One sentence = one idea.
- Front-load the concrete noun.
- Use numbers where they prove scale.
- Replace long stacks with grouped capabilities.
- Prefer verbs of delivery: built, reduced, migrated, secured, industrialized, structured, audited.

| "leadership technique" | "team built from X to Y, architecture reviews, coaching, standards adopted" |
| "optimisation" | "cost reduction, deployment time reduction, lower incident rate, faster delivery" |

## Final Pass

Run this checklist before publishing:
- The first 3 lines can survive alone.
- The top 3 proof points are visible without scrolling too far.
- The same strategic keywords appear in consistent form.
- Every impressive claim is defensible.
- The copy contains no private implementation detail that should stay internal.
