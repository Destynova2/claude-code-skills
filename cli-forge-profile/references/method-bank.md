## Evidence-Based Principles

### 1. Scan-First Writing

Use for LinkedIn, Reddit, GitHub profile READMEs, portfolio pages, and maintained `.md` profile files.

Rules:
- Put the conclusion first.
- Make the first 2 paragraphs carry the core value.
- Start headings, bullets, and paragraphs with information-carrying words.
- Cut continuous prose into coherent topical blocks.
- Prefer concise, scannable copy over narrative build-up.

Source base:
- NN/g F-pattern research: https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content-discovered/
- NN/g "How Little Do Users Read?": https://www.nngroup.com/articles/how-little-do-users-read/
- NN/g "Be Succinct!": https://www.nngroup.com/articles/be-succinct-writing-for-the-web/
- NN/g inverted pyramid: https://www.nngroup.com/articles/inverted-pyramids-in-cyberspace/

### 2. Resume as Evidence, Not Biography

Use for CV/resume rewrites.

Rules:
- Tailor the CV to the target position or mission.
- Use active, specific, fact-based language.
- Quantify and qualify outcomes.
- Avoid narrative style, first-person pronouns, slang, pictures, and references.
- Prefer accomplishments and contributions over responsibilities.
- Put skills in context inside experience bullets, not only in a skills block.

Source base:
- Harvard resume guide: https://careerservices.fas.harvard.edu/resources/create-a-strong-resume/
- MIT resume guide: https://capd.mit.edu/resources/resumes/

### 3. Applied-Skill Proof

Use for LinkedIn skills, GitHub profile, portfolio, and freelance positioning.

Rules:
- A skill is stronger when attached to a role, project, credential, repo, case study, or public artifact.
- Skills lists should support search, but proof sections should establish trust.
- Prefer fewer, coherent skills over broad keyword stuffing.

Source base:
- LinkedIn add/remove skills: https://www.linkedin.com/help/linkedin/answer/a549047
- LinkedIn display order of skills: https://www.linkedin.com/help/linkedin/answer/a568137
- LinkedIn Skill Assessments page: https://www.linkedin.com/help/linkedin/answer/a507663

### 4. Portfolio Proof Hierarchy

Use for GitHub and public portfolio profiles.

Rules:
- Lead with the work visitors should inspect first.
- Pin only projects that reinforce the same positioning.
- Each project should answer: who is it for, what problem it solves, what proof exists.

Source base:
- GitHub profile README: https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme
- GitHub pinned items: https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile

### 5. Community Trust Before Promotion

Use for Reddit/community bios and launch posts.

Rules:
- Post authentic content into communities where the user has real interest.
- Share lessons, incidents, benchmarks, or implementation notes before linking a product.
- If linking owned work, disclose the relationship and keep frequency low.
- Do not ask for votes or coordinate attention.

Source base:
- Reddit spam policy: https://support.reddithelp.com/hc/en-us/articles/360043504051-Spam
- Reddiquette: https://support.reddithelp.com/hc/en-us/articles/205926439-Reddiquette

## Copy Frameworks

Use these as lenses, not as research-backed guarantees. A framework never overrides verified facts, confidentiality, platform constraints, or the user's real voice.

### BLUF / Inverted Pyramid

Best for: LinkedIn About first lines, CV profile, Reddit posts, GitHub profile intro.

Template:

```text
Conclusion / offer.
Best proof.
Scope and mechanisms.
Context and details.
CTA or next step.
```

### CAR / STAR for Proof Bullets

Best for: experience bullets and case studies.

CAR:
- Context: situation or constraint.
- Action: what the person changed.
- Result: measurable outcome or durable proof.

STAR:
- Situation, Task, Action, Result.

For profile copy, collapse this into one bullet:

```text
Action verb + scope + mechanism + result + proof/constraint.
```

### SUCCESs From "Made to Stick"

Best for: memorable positioning and public bios.

Adapt as:
- Simple: one core positioning.
- Unexpected: one differentiated constraint or proof.
- Concrete: real tools, sectors, artifacts, numbers.
- Credible: audits, repos, talks, client contexts.
- Emotional: the buyer's risk, not personal drama.
- Story: trajectory from problem to delivered outcome.

Source:
- Heath Brothers, "Made to Stick": https://heathbrothers.com/books/made-to-stick/

### StoryBrand-Style Clarity

Best for: freelance service pages and commercial positioning.

Adapt as:
- The buyer is the hero, not the consultant.
- The consultant is the guide.
- Lead with the buyer's problem.
- Name the plan or deliverables.
- Make the call to action obvious.
- Reduce cognitive load with repeatable soundbites.

Source:
- StoryBrand: https://storybrand.com/
